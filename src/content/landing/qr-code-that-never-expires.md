You print a thousand flyers, and six months later the code on them leads to a "your subscription has ended" page. It happens all the time, and it is not a bug. It is how a lot of free QR code sites make money. This page explains why codes die, and how to make one that will not.

## Static and dynamic codes

A **static** code stores your content inside the pattern of dots. A web address, a WiFi password, a contact card: all of it is in the square. A phone reads the dots and acts on them. No other computer is involved.

A **dynamic** code stores a short web address on the vendor's server. The phone visits that address, and the server forwards it to your page. That lets the vendor count scans and lets you change the destination later, but it also means the code only works while the vendor's server answers. Stop paying, and the vendor can turn it off, show an advert, or ask for money. See [the full comparison](/dynamic-vs-static-qr-codes/).

## How to make one that lasts

1. Use a static code. ForeverQR only makes static codes, so everything you make here qualifies.
2. Put the content you need in the code itself where you can: contact details, WiFi, plain text, an event.
3. For web pages, point the code at an address you own and control. If you own the domain, you can always make it lead where you want.
4. Keep a copy of the SVG file somewhere safe, so you can reprint at any size.

## An honest limit

A code that never expires is only as permanent as what it points to. If your web page disappears, a perfectly valid code leads nowhere. That is the part you control. Keep the domain renewed, keep a redirect when pages move, and the code outlives its printing.
